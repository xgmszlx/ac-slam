# Input adapter audit

[Source] One existing non-CD technical input is selected: v13 technical `target_A/seed_81001/canonical_prefix.jsonl` (33 records, SHA `4eddfa84d601f04bf4b86f52dca819c4ccd83c5476fdb48cf1e48f0c76255bde`). This history predates CD and is already used as an independent technical smoke input in A0; no CD treatment/endpoint is opened. Fixed split is H indices [0,20), C [20,33). The split is made before any new backend replay and is not selected for closure performance.

[Code] Acquisition in `controlled_probe_capture.py` records latest `/odom` base pose plus known laser mounting: laser_x=base_x+0.2*cos(yaw), laser_y=base_y+0.2*sin(yaw). Inverting this arithmetic yields the corresponding recorded base odom sample. Map3 `p3at.inc` mounting is [0.2,0,-0.2,0] and has no yaw offset. These are recorded odometry samples, not ground truth or invented new poses.

[Config] Laser has 901 float32 readings, angle min/max ±1.5707963705062866, increment 0.003490658476948738, range min0/max25m. All are transferred unchanged through LaserScan float32 fields. Audit checks finite data, sample count, ordered stamps and base->laser roundtrip. Laser TF is static [0.2,0,-0.2] with identity rotation; odom->base samples are the inverse geometry; map->odom remains mapper-owned. The empty recorded frame_id is assigned a new logical name `cd_b0_laser`, not interpreted as a recovered original name.

[Limitation] Canonical timestamps were previously normalized to 0.1s in original record order. Original stamp/odom synchronization latency is unavailable; the capture stored latest odom and discarded its timestamp. The adapter uses this declared technical sample pairing, shifts time origin +10s to avoid ROS Time(0) semantics, and does not claim original acquisition timing. Missing scan_time/time_increment remain zero/unknown; intensities empty. SDK does not use these fields for matching. No original frozen file is rewritten, nor are new odometry observations fabricated.

[Inference] Feasible for a deterministic technical continuation comparison under this explicit replay contract; insufficient for claims about original hardware motion distortion or latency. Official filtering may accept fewer than 33 inputs; node equality with the old Karto is not required. Wire serialized hashes, global header sequence and identical C messages are checked in every restore.
