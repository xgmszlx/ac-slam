### 1.2 这不是"漏了一项交叉协方差"那么简单

审查指出的公式是对的：

```
Cov(Δe) = Σ_k + Σ_{k−1} − Cov(e_k,e_{k−1}) − Cov(e_{k−1},e_k)
```

但实测显示**交叉项只占分母 4–7%**，真正的问题是：误差序列的滞后自相关高达
**0.974–0.995**，一条近乎完全相关的序列，其**一阶差分**的方差比单帧方差小三个数量级。
用 `Σ_k+Σ_{k−1}` 当分母，等于拿"两帧各自的不确定性"去除"一个几乎不动的偏置的抖动"，
两者**不是同一个随机变量**。

所以 `NEES_rel ≈ 1.0–1.5` 落在 χ²₃ 中位值 2.366 附近，**是巧合，不是标定正确**。

- ❌ 撤回："相对口径下逐帧协方差主体量级正确（0.43–0.65×，略保守）"
- ❌ 撤回："逐帧偏航精度估得基本正确（`z_θ = 1.03/0.81`）"
- ❌ 撤回："全局尺度救不回来，所以是形状问题"（该论证比较了 `√tr(Σ_xy)` 与 `‖e_xy‖`

## 3. 预登记与实现不一致（确认）

`PREREG.md` §3.4 写的是

```
e_k = log_SE2( (T_gt→map · ξ^gt_k)⁻¹ · ξ^hector_k )
```

`analysis/l1_g1_analysis.py:184–187` 实际是

```python
ex  = v['hx'] - al_pose[0, 2]
ey  = v['hy'] - al_pose[1, 2]
eth = wrap(v['hyaw'] - atan2(...))
```

即**世界系位置差 + 偏航差**，不是 SE(2) 对数映射。

这不是笔误：设计时我考虑过两种口径并**选择了世界系**（因为 `H` 是世界系），
但**没有回改冻结的预登记文本**。这是预登记完整性的失效，比代码写错更严重。
`PREREG.md` §3.4 的公式应视为**未生效**；实际执行的是世界系口径，且未预先声明。
