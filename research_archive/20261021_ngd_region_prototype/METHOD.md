# 已执行的局部区域原型

版本：2026-10-21；完整冻结值在protocol/design_frozen.json。这里描述实际测试的代码，不是未实现方案。原型没有训练、语义新类别、GMM/HMM、原生深度修改或新优化器。

## 决策的数据流

`GrabImageRGBD → 原PredictCurrentMask → 本轮区域模块 → 原静态LK/ORB与优化 → RecordCompleted`。

M0跳过Apply/Generate/运动估计，仅执行共同只读诊断。M1/M2共享**没有mode参数的Generate**。M2的Cache只在上一帧全部跟踪完成后保存：原灰度/depth、当时Tcw、地图ID，以及非bad、Observations≥3、原外点标志未拒绝的MapPoint/像素。它们是原系统接受的关联，不是静态真值。

决策时只读取这个旧Cache与当前RGB-D/mask。时间必须递增、间隔≤0.2s、地图一致、旧状态OK；否则原mask返回。不使用当前最终MapPoint关联/pose、未来帧或GT。每帧结束才更新Cache供下一帧使用，避免循环依赖。

关键帧的旧像素使用mvKeys原始坐标，非关键帧的旧LK坐标按其实际原始图像域处理；前置LK保持原始像素，PnP用K/dist处理这些原始像素；3D反投影先undistortPoints归一化再乘depth。没有修正或替换原NGD自己的LK实现。

## M1：深度连通候选

使用4×4网格，含原mask像素的网格作为种子侧。只从与mask四邻接、有效depth且深度差≤0.3m的未遮罩网格生长。生长同时限制相邻深度差和相对该种子anchor深度差≤0.3m，避免渐变链无限跨面。

候选只包含原mask外且有效depth的像素；按面积固定排序，最多4个，至少64像素，单区域≤图像35%，候选总新增≤45%。M1直接接受这些候选；合并后超过80%则拒绝该新增区域并保留原mask。**这是新增提案的公共安全门，原YOLO的80%清零代码完全不变**。没有候选、无效depth、不接触、超面积等情况不扩张，不进行全图未知物体搜索。

测试时相同输入、M1/M2生成的候选哈希相同。实际完整运行的mask、pose和异步历史可以不同，故不能保证不同运行逐帧候选完全相同；本轮M1中止且其缓存丢失，更不能冒称已作正式候选一一配对。

## M2：区域整体接受检验

1. 将上一帧已接受地图关联经新计算的前向/反向LK对应到当前原始图像。候选与原mask之外的当前对应用于独立前置PnP-RANSAC：100次、5px、0.99，至少20内点、占用≥4个8×6格，并检查3D非共线分布/有限值。背景PnP不是当前原生跟踪的结果；也不是已证明正确的静态相机真值。
2. 候选内部以15px网格采样，最多400点；当前→旧帧LK并做往返≤1.5px检查。两端depth≥0.05m，3×3至少5个有效邻居且深度跨度≤0.3m，才构成局部3D对应。这些筛选仅服务区域判定，不从原生特征集合直接删除任何点。
3. 至少18对。按固定顺序`index%3==0`留作验证，其余拟合。用训练点做100次RANSAC，三点SVD/Kabsch得到刚体变换H；至少8训练内点，距离门0.05m。训练和验证点在两端都检查第二/第一奇异值比≥0.02、RMS展开≥0.02m，排除近共线/过小区域；验证像素至少覆盖4个20px格且宽高≥20px。允许非共线平面，不把这里的分布检查叫成完整位姿可观性证明。

背景变换是`T_bg = Tcw_current_PnP × inverse(Tcw_previous_completed)`。区域拟合为：

`H = argmin_(R∈SO(3),t) Σ_train ||R X_previous + t − X_current||²`。

留出集比较：

`E_static = median ||T_bg X_previous − X_current||`；
`E_rigid  = median ||H X_previous − X_current||`。

只有留出点≥6、至少80%留出残差≤0.05m、`E_rigid≤0.05m`且`E_static−E_rigid>0.05m`才进入接受阶段。再检查两种假设投影在图内、正depth和较近表面遮挡：有效验证点不足6或遮挡不明确超过1/3时拒绝。少量遮挡仍计入原中位误差并另行计数；这些启发式不保证所有遮挡或错配都排除。

区域H仅由训练点估计，验证点不参与RANSAC/重拟合。留出点仍来自同一视频和相邻网格，不能当独立统计实验。背景PnP使用RANSAC自身支持，没有额外背景留出集。深度、像素、旧pose和地图误差可能相关，**没有校准的动态概率或噪声协方差主张**。

4. 接受时把整个候选加入mask，其他情况原mask保留。新增部分通过原Frame的mask筛选和原LK的mask判断发挥作用；不直接改描述子、depth、匹配门限、鲁棒核或优化公式。被接受mask进入原有历史缓存，仍由原传播代码处理；不同模式可能产生不同历史。辅助RANSAC使用局部随机发生器，前置PnP保存/恢复OpenCV线程RNG，避免额外消耗原跟踪随机流。

## 可观测的处理链

- Frame原mask判断处统计原提取特征、原mask/新增mask导致的实际删除、实际保留。没有用独立ORB探针替代。
- ORBmatcher原LK状态有效后、原mask判断处统计对应是否被原/新增mask挡掉。
- 原生PnP-RANSAC内点另计；它不是PoseOptimization边。
- 原PoseOptimization只读统计图的对应边数和原外点裁决后的内点数。记录每帧最后一次及多次调用累计；累计不是唯一约束数量，也不代表LBA/回环完整图或Jacobian影响力。
- 共同入口记录TrackRGBD实际返回Twc、公开GetTrackingState、地图ID和map数、mask哈希/面积、区域理由、完整API时间；模块另用CLOCK_THREAD_CPUTIME_ID记录主线程CPU。M2缓存和共同日志开销仍在完整API/进程成本中。

## 实际安全边界

23个软件检查通过，包括空mask/无候选、无效或不连通depth、多候选、超面积、退化、留出集反例、PnP失败、非有限值和非零畸变。它们不是定位收益证明，也没有覆盖所有原生集成前提。

**M1正式运行仍触发原生LK断言并中止**。模块内OpenCV异常回退并不能拦截后续原生跟踪的所有失败；面积安全不保证保留足够跟踪输入。当前实现没有满足整条SLAM链的安全回退要求，不能称可部署。本轮不在看到ATE后改安全门或修原生LK，也不重跑。
