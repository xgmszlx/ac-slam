## 2. 对 v1 的三条修正

### 修正 1：轨迹位置 ≠ 修改时刻

v1 写过"损坏点在 168/265/316，离回环 200 帧，所以与回环无关"。**这个推论不成立**，本版撤回。

能证明的：
- 跟踪当刻的逐帧记录在 165→168、250→265、299→316 三个区间只动了 0.040/0.070/0.101 m，而导出轨迹动了 0.479/0.863/0.840 m；
- 因此这些关键帧位姿在被创建之后**必然**被改过（跟踪期不是这个形状）。

不能证明的：
- 改动**发生在什么时刻**。候选集合包含局部 BA、Essential Graph、GBA，全部落在 `(关键帧创建, 导出)` 区间内；回环在 16.42 s，晚于帧 168/265/316 的创建时刻，完全在候选集内。
- 也无法区分"一次大规模变形"与"多次小变形累积"。

→ 结论降级为：**最终地图存在非刚性变形（事实）；变形由哪个优化阶段引入（UNKNOWN）**。要定位，必须给每次 `InformNewBigChange`、EG 起止、GBA 起止、关键帧位姿写入打时间戳（§8.1 的低成本方案）。

### 修正 2：ATE 本身有效，不可主张的是归因

v1 写过"ATE 排序不可用"。**过强，本版修正。**

- ATE（单一 SE(3)、无尺度、全量匹配）是有效的全局精度度量，其数学定义没问题；
- 真正的问题是三条：
  1. **单次** ATE 差不能归因于算法改动；
  2. 轨迹内部不连续时，ATE 对"对齐在哪一段"敏感：M2 前后段隐含坐标系差 19.29°/0.272 m，而其 [501,588] 段与在线记录只差 4.5 mm，却得到 0.0253 m 与 0.3974 m 两个 ATE —— **同一批点差 16 倍**；
  3. 因此 ATE 必须与"轨迹内部一致性"一起报告，否则数字不可比。

→ 正确表述：**ATE 有效，但单次 ATE 差异不构成算法收益证据；报告 ATE 时必须同时报告内部一致性与对齐敏感性。**

### 修正 3：干预稀疏不构成"无效"证据

v1 写过"0.2% 的删除量低于系统噪声"。**推理不成立，本版修正。**

- 稀疏干预完全可能通过改变关键帧插入、地图关联、回环候选而产生放大效应；比例小 ≠ 效应小；
- 现有证据只能支持：**当前设置下没有可重复、可归因的净收益**；
- 要判定"方法有效/无效"，需要剂量-响应（不同干预强度）+ 同条件重复，而不是按比例推断。

## 4. 事件归属（源码级）

`LoopClosing.cc` 中能成对打印 `Local Mapping STOP/RELEASE` 的只有三处：

| 位置 | 触发方 | 本 run 是否出现 |
|---|---|---|
| `CorrectLoop` L975 RequestStop → L1210 Release（EG 在 L1181） | 回环 | 是（帧 490→492） |
| `MergeLocal` L1248 RequestStop → L1639 Release | 多图合并 | 否（全日志无 `*Merge detected`） |
| `RunGlobalBundleAdjustment` L2320 RequestStop → L2494 Release（L2505 `Map updated!`） | GBA 落地 | 是（帧 499→500） |

- 非惯性 RGB-D ⇒ `isImuInitialized()==false` ⇒ GBA 启动条件恒真（L1198–1206）；
- `Verbose::VERBOSITY_QUIET` 屏蔽 `VERBOSITY_NORMAL`，故 `Starting/Global Bundle Adjustment finished` 不出现——**预期行为**；
- GBA 从帧 492 起、帧 499 落地，墙钟约 235 ms。对 101 个关键帧偏快，是需要计时确认的点（§8.1）。

**历史先例（重要）**：`20261019_depth_repeats/results/B0_03` 发生过 `*Merge detected`（地图合并，非回环），日志同样成对出现 2 组 STOP/RELEASE，其 Online↔Exported 差达 0.748 m / 34.9°，在线 ATE 0.856 而导出 ATE 0.105。**同样签名的事件可以在完全没有回环的情况下产生同量级的记录性分裂**——这支持"导出与在线是两套记录"的解释，也再次说明不能仅凭差异大小反推回环。

## 8. 后续唯一有界实验，以及低成本前置项

### 8.1 三项零成本前置（不改算法、不新增运行）

1. **开 `-DREGISTER_TIMES` 重编**：`System::Shutdown()` 会调用 `PrintTimeStats()`，直接输出 `vdGBA_ms`、`nFGBA_exec`、`nFGBA_abort` 与 GBA 时刻的 KF/MP 数。**不需要改一行 `LoopClosing.cc`**。
2. **地图完整性门限进流水线**（每 run 自动算，超限即标 `INVALID`）：
   - 关键帧最大速度 ≤ 1.2 m/s 且 ≤ 90°/s（M2 4.77 m/s、122.7°/s → 无效；M0_05 3.24 m/s → 也应标无效）
   - 路径比 导出/在线 ∈ [0.9, 1.1]（M2 1.519 → 无效）
   - 前后段刚体残差 ≤ 0.05 m（M2 0.358 → 无效）
3. **GT 轴系双重约定**：同一次运行用两种约定各算一遍 RPEr，差值 > 5° 即判定该指标未定，不引用。

### 8.2 唯一推荐运行集

`LC_OFF_M0_R1` / `R2` / `R3`——同一二进制、`loopClosing: 0`、同协议、开 `REGISTER_TIMES`、附完整性门限。

源码确认该开关可用：`System.cc` L101–105 读参数 → L213 传入 → `LoopClosing.cc` L327 `if(!mbActiveLC) return false;`（`NewDetectCommonRegions` 首行）。**副作用**：此时该函数在弹出队列前就返回，`mlpLoopKeyFrameQueue` 只进不出（20 s 内约 100 个 KF 常驻，功能无害，需在报告中注明）。

### 8.3 判决规则（替代 v1 的 0.05 m 硬阈值）

不用统一阈值，用**效应 / 基线波动比**，并按指标分别给量纲：

| 指标 | 基线波动（Bonn box，4 次） | 可主张的最小效应（建议 ≥ 1× 极差） |
|---|---|---|
| ATE | 0.2060 m | ≥ 0.21 m |
| RPEt | 0.0452 m | ≥ 0.05 m |
| RPEr | 0.853° | ≥ 0.9°（且需先修 GT 约定） |
| KF 数 | 32 | 作为诊断量，不作结论 |

- 三次重复只作**初步筛查**，不得称为统计显著性检验；
- 若预期收益 < 上表可测门限 ⇒ 判定"当前条件下不适合做算法比较"，先解决重复性；
- 若不通过，`M2` 线标记 `ARCHIVED — CAUSAL BENEFIT NOT ESTABLISHED`，不再围绕它寻找创新点。
