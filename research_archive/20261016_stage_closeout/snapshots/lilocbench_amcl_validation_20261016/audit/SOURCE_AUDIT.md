# Source / coordinate / time audit

Fixed official navigation tag 1.17.3, commit `f13af47ee2bca6c3bf99db2965e46e55303f6e66`. Installed AMCL `1.17.3-1focal.20250521.001518`, dpkg verification empty and all nine installed public headers identical. This establishes version/header agreement, not byte-for-byte reconstruction of the installed binary.

- A0 likelihood_field uses floor beam stride and `1 + sum(pz^3)`; A1/A2 likelihood_field_prob use ceil stride and product likelihood via log-sum. A0/A1 are different observation models, not a beam-skip ablation.
- A2 only skips while `set->converged`. Native convergence tests every particle's x/y distance to the unweighted mean against 0.5 m; it is not GT correctness and has no yaw test.
- Beam agreement counts particles (not posterior probability mass) within beam_skip_distance. Strict `count / particle_count > threshold` retains a slot. At skipped_slots >= allocated_slots * error_threshold it falls back to all allocated slots.
- Native code loops over max_beams slots in mask/fallback integration. With 811 ranges and max_beams=100, the prob-model stride is 9 and only 91 physical slots are sampled. The remaining 9 allocated slots must not be called 9 observed laser beams. Diagnostic logs distinguish allocated and physical slots; physical slots may also contain invalid/max-range readings.
- `reallocTempData` zero-initializes temporary slots. The all-slot fallback may include untouched zero slots and yield log(0). This is a source-supported implementation concern, not evidence of an observed fallback or of a new research mechanism. Runtime evidence and its limits are reported separately. No fix was made.
- Native `pf_alloc` seeds from wall time and has no seed ROS parameter. Source copy changes seed selection only when AMCL_EXPERIMENT_SEED is supplied, and prints exact seed. This changes the random realization, is not only logging, and leaves sampling/weight/resampling formulas intact. Other diagnostic edits only read counters and emit scan IDs / beam states; costs are retained. No bitwise identity with installed binary is claimed.

## Why the native offline interface

An initial launch used an unsupported absolute node type and did not deliver scans. A second, completed 8x external ROS replay had multi-second TF backlog and is classified TECHNICALLY_INVALID for science; its original trajectory/metrics remain. We did not interpret its 3.06 m error as map-change failure.

The installed official executable already supports `--run-from-bag`. This implementation hardcodes topic names `tf` and `base_scan`. Derived bags only alias the original `/tf` and front scanner topics; raw serialization, header stamps, record stamps, order and counts are verified by a framed readback hash. No scan generation, range changes, deskew or GT transform is added. `/tf_static` is not consumed by this native interface; its needed direct odom->base_link and base_link->scan_front_link chains are already in original dynamic `/tf`. The latter extrinsic is constant throughout both original bags.

Native mode puts original TF into its own buffer and directly supplies scans to its native message filter. No asynchronous external player is run; the estimator's normal `/scan` subscription has no publisher, avoiding duplicate sensor input. Its `/base_scan` publication is observed only for provenance. The official function also republishes `/tf` while directly inserting it; equal-timestamp/equal-value duplicate-TF warnings are expected and are not different poses or competing publishers. Actual multi-parent/publisher and extrapolation are audited separately.

`/use_sim_time=false` in native mode: wall time is used for administration, timers, runtime and PoseArray publication stamps. Sensor/action propagation uses original scan header timestamps, original stamped odom TF and pose deltas. The AMCL pose output is stamped with the original scan time; evaluation never pairs wall-time particle stamps to GT. Sampled particle clouds are preserved with their actual receipt/ROS times, without pretending to have precise scan identity. Main diagnostics provide actual scan identities at sensor updates. Initial pose is loaded once from prewritten parameters, not a GT stream. No `/clock` simulator is asserted in this native mode.

## Evaluation

Official evaluator commit `68e86f33ae3ff660444b92093fb98ca4d5633b46`, unmodified. It projects to XY/yaw, interpolates estimator poses to GT stamps and does no spatial best-fit alignment. It repeats endpoint poses outside native trajectory extent. Report this behavior and additional span / gap-support and native-stamp metrics; do not call interpolation a returned pose or per-scan tracking success.

Official convergence plot incorrectly compares radian rotation error with `r2d(5)` for a five-degree configuration; numerical scoring correctly uses `d2r`. We retain the source and official score, and exclude that plot as convergence evidence. Independent controls include a fixed 1 m displacement that remains an error and a 0.1 rad yaw check. One initial endpoint-control assertion failed at a 1.39e-17 SLERP matrix reconstruction difference; initial script/log retained. Translation equality is exact, rotation reconstruction is tested numerically at 1e-12; trajectory acceptance rules did not change.

## Final corrections discovered during execution

`pf_pdf_gaussian_alloc` also calls `srand48(++pf_pdf_seed)`, with initial counter zero. Thus pf_alloc-only control in diagnostic v1 did NOT deliver nominal seed1701/1702 to the initial particle distribution. Existing v1 runs, including the already-started second static A0, are retained and annotated actual initial Gaussian seed1 in a separate ledger. The first A1 source runs exactly reproduce the installed A1 trajectories in the tested sequences; this is observed agreement, not a general numerical-invariance guarantee.

A v2 copy (old library/source retained) adds RNG selection at the actual Gaussian reseed point, preserving the native increment sequence when unset and offsetting it when a fixed seed is requested. Only the five unstarted slots use v2, with actual first Gaussian seed1702 printed and checked. A two-call allocator unit test independently confirms four drand48 values exactly for effective seeds1702 and1703. No whole trajectory rerun was added. Static A0 remains two same-seed1 runs, not an independent two-seed test. Its accepted scan-update sets differ by48 stamps each despite equal967 counts; the input bag is identical. This runtime/update-selection variation is retained. A1/A2 changed-map pairs have identical708 exact sensor-update stamps for each effective seed, so their differences are not obtained by dropping different difficult scan updates.

For these811-range scans and max_beams100, A0 actually samples102 slots (floor stride8), whereas A1/A2 sample91 (ceil stride9). The common parameter is a budget, not a guarantee of identical actual counts across these two native implementations. A0/A1 cannot isolate weighting independently of beam sampling. A1/A2 do use the same91 physical slots and same update identities.

Recovery alphas remain native defaults slow0.001/fast0.1. This enables augmented-MCL uniform random-particle injection, even though initialization is local and no global_localization service is called. The injection frequency/particle ancestry was not logged. Consequently it is UNKNOWN how much of the large jumps comes from recovery injection versus observation weighting/aliasing. Merely being marked converged does not resolve this. A recovery-off parameter control is preferable to introducing a new estimator now.
